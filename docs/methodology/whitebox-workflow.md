# ホワイトボックス診断ワークフロー

未知の Web アプリケーションを読むときの基本手順です。

## 1. 正常系の挙動を理解する

- この機能は何をするものか
- どのHTTPリクエストで到達するか
- 認証は必要か
- 実行するとレスポンスやサーバー状態がどう変わるか

## 2. アプリケーション構造を把握する

```text
Route
  ↓
Controller / Handler
  ↓
Request Data
  ↓
Validation / Transformation
  ↓
Business Logic
  ↓
DB / Template / File / HTTP / Command / Deserialization
```

## 3. データフローを両方向から追う

### Source → Sink

攻撃者が制御できる入力から開始し、最終的にどこへ届くかを追います。

### Sink → Source

危険な処理から逆方向にたどり、攻撃者入力が到達可能か確認します。

明確なSinkだけでなく、認証、認可、状態遷移、Business Logic も確認します。

## 4. Primitive を考える

脆弱性名だけで終わらせず、「この脆弱性を悪用すると、攻撃者は新しく何ができるか」を考えます。

例:

- DBの任意データを読める
- サーバーから任意のHTTPリクエストを送れる
- 任意ファイルを読める
- 任意ファイルを書ける
- テンプレート式を評価できる
- 他ユーザーとして操作できる
- 内部専用機能へ到達できる

## 5. Exploit を構築する

制約条件を理解し、まず手動でExploitを成立させます。その後、自動化可能な部分を Python PoC に落とします。

## 6. 再現性を確認する

対象を初期状態へ戻し、クリーンな状態から単一のPoCで再現できることを確認します。
